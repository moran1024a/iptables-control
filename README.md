# iptables-control（ictl）

轻量的 IPv4 端口转发管理工具。通过 Web 面板管理多台服务器，或使用 `ipt.sh` 在单台服务器上独立管理转发。

**0.6.0-rc.5（测试版）** 支持可视化拓扑、多入口与多目标、主副 IP、订阅分享和 7 天网络质量图。主动节点使用 Go + nftables 和长连接，被动节点使用 Bash + iptables，按需同步。转发节点无需安装代理核心，SS／SS2022／VLESS Reality 等目标服务需自行准备。

## 安装

管理多台服务器时，安装**服务端 + 节点 Agent**；只管理本机时，安装**单机脚本**即可。以下命令固定使用 0.6.0-rc.5，已有部署请先阅读[升级说明](#升级)。

### 服务端

准备一台已安装并启动 Docker 的 Linux 服务器，使用有 Docker 权限的账号执行：

```bash
curl -fsSL https://github.com/moran1024a/iptables-control/releases/download/v0.6.0-rc.5/install-server.sh | bash
```

安装完成后，打开输出的**完整面板地址**。默认账号为 `admin`，密码为 `admin_pass`，首次登录必须修改。

默认端口为 `8730`，容器名为 `ictl-server`，数据卷为 `ictl-data`。如需指定端口或使用国内镜像：

```bash
curl -fsSL https://github.com/moran1024a/iptables-control/releases/download/v0.6.0-rc.5/install-server.sh | bash -s -- --port 9000 --mirror
```

主动 Agent 必须使用有可信证书的 HTTPS。请配置支持 WebSocket 的反向代理，转发至服务端的实际端口，并在面板“设置 → 对外地址”填写节点可访问的 HTTPS 地址。

### 节点 Agent

节点需要使用 systemd 的 Linux，并以 root 权限安装。

- **主动**：amd64／arm64，Linux 5.10+、nftables 1.0+、iproute2、conntrack-tools，使用 HTTPS／WSS。
- **被动**：Bash、iptables（含 save／restore、addrtype、conntrack）、iproute2、getent、conntrack-tools。
- 两者都需要 curl、openssl 1.1.1+ 和 flock。安装器可在 Debian／Ubuntu 安装缺少的依赖，其他系统需自行准备。

1. 在面板“节点”中新增节点，填写名称、主 IPv4／域名，选择主动或被动模式。
2. 打开节点详情，复制“一键接入”命令，在**对应节点服务器**执行。
3. 回到面板确认节点状态和 IP 识别结果。以后可运行 `sudo ictl` 打开节点管理菜单。

允许的入站端口可填写 `10000-20000,30000` 这样的范围和列表，并需在云安全组及系统防火墙中放行相应 TCP／UDP 流量。副 IP 和特殊网络的设置见[节点与 IP](#节点与-ip)。

### 单机脚本

不需要服务端或 Agent。在使用 systemd 的 Linux 服务器执行：

```bash
curl -fsSL https://github.com/moran1024a/iptables-control/releases/download/v0.6.0-rc.5/ipt.sh -o ipt.sh.download &&
sudo install -m 755 ipt.sh.download /root/ipt.sh.new &&
sudo mv -f /root/ipt.sh.new /root/ipt.sh &&
sudo bash /root/ipt.sh
```

首次运行会检查并安装缺少的 Python 3.8+、iptables 和 iproute2 软件包。后续运行 `sudo bash /root/ipt.sh` 即可进入菜单。

## 升级

**顺序：先升级服务端，再升级节点 Agent 和单机脚本。**

### 服务端升级

重新执行[服务端安装命令](#服务端)。安装器沿用现有端口和数据挂载，保留升级前数据库备份；新容器启动或就绪检查失败时尝试恢复旧容器和数据库。相同版本需要重建时，将命令末尾改为 `| bash -s -- --force`。 使用自定义 Docker 网络、额外挂载、环境变量或资源限制时，安装器会在停止服务前提示退出，请沿用原 Docker Compose 或部署命令更换镜像版本。

**从 0.6.0 RC1／RC2／RC3／RC4 升级：保留全部数据，包括已有目标地址和节点标签。RC1／RC2 的节点初始无标签；RC1 的节点权重默认为 0，链路自动灾备默认关闭。**

**从 0.5.3 升级：仅保留以下节点信息，清空旧业务数据。更早版本请先升级至 0.5.3。**

- 保留节点列表、密钥、分组顺序、主副 IP、主被动模式、自动更新与唤醒设置，以及管理员账号、面板和同步地址。
- **清空目标、链路、配置、订阅和历史记录**，升级后需要重新创建。请在升级前另存需要的目标链接和配置。
- 节点下一次成功同步会清理旧转发规则；清理确认前，旧端口仍保留占用。远端节点上的单机脚本规则不受影响。
- 主动节点开启自动更新后自动更新到本版。被动节点首次迁移需在本机运行 `sudo ictl --sync`，之后仍按原有手动／唤醒方式同步。

数据库版本为 **602**，从 RC1／RC2 迁移数据库时另保留 `ictl.db.pre-0.6.0-rc.3.bak`。Docker 升级备份为 `/data/ictl.db.pre-deploy-*.bak`，节点导入另保留 `ictl.db.pre-0.6.0.bak`。回退需同时恢复升级前数据库与对应旧镜像；已同步的节点也需要重新同步旧配置，不能保证升级期间转发不中断。

### 节点 Agent 升级

本版主动 Agent、被动 Agent 和管理器均为 **0.6.0-rc.5**。主动节点开启自动更新后自动升级；被动节点需在本机更新一次，之后普通同步自动复用已安装组件。在节点执行：

```bash
sudo ictl --update
sudo ictl --sync
```

存在未完成的切换时，先执行 `sudo ictl --sync` 完成确认；提示交接中断时按提示执行 `sudo ictl --recover`。更新只替换当前类型，主被动切换见[切换模式](#切换模式)。

主动 Agent 在 `AUTO_UPDATE=1` 时自动更新同类型程序，转发配置异常不会阻止更新通知。被动 Agent 的程序升级需在本机手动执行，远程唤醒只同步配置。本版不再提供旧版轮询 Agent，旧部署请先通过 0.5.3 完成接入。

安装器会处理可识别的 `/root/ictl.sh`、`/ictl.sh` 旧入口。此前安装失败留下 `switch-work` 的节点，请保留该目录，使用新版一键接入命令恢复；不要直接删除交接记录。

### 单机脚本升级

重新执行[单机脚本安装命令](#单机脚本)，更新到 **3.2.3**，以识别新版 Agent 的端口记录。若原脚本不在 `/root/ipt.sh`，请将安装路径改为原路径，保证开机任务和定时任务使用新版。更新后进入菜单检查转发列表。

## 卸载与删除

### 卸载服务端

删除容器和镜像，保留数据卷：

```bash
curl -fsSL https://github.com/moran1024a/iptables-control/releases/download/v0.6.0-rc.5/install-server.sh | bash -s -- --uninstall
```

追加 `--purge` 会永久删除默认数据卷中的全部数据。卸载服务端不会清理远端节点规则；完整停用时，请先处理节点。

### 卸载节点 Agent

1. 从相关链路中移除该节点，等待旧规则清理，再在面板删除节点。
2. 等待节点完成删除同步；未启用唤醒或唤醒失败的被动节点，需运行 `sudo ictl --sync`。
3. 在节点卸载 Agent：

```bash
sudo ictl --uninstall
```

命令会询问确认，并删除该 Agent 的规则、配置和服务；非交互执行可加 `-y`。

### 停用单机脚本

先运行 `sudo bash /root/ipt.sh`，通过“删除转发”清空由它管理的规则，再停用开机恢复和定时刷新：

```bash
sudo systemctl disable --now ipt-forward-selfcheck.timer ipt-forward-selfcheck.service
```

完成后可删除脚本。配置目录 `/root/iptables-forward-conf/` 和备份目录 `/root/iptables-backup/` 可按需保留。仅删除脚本或停止服务不会清除已有转发。

### 删除面板对象

删除节点或目标前，需先从引用它的链路中移除。切换和清理期间的引用需等待节点确认后释放。删除链路后，端口也会在清理确认后释放；配置页中的条目由链路生成。

## 使用指南

### 创建第一条转发

| 对象 | 用途 | 示例 |
| --- | --- | --- |
| 节点 | 安装了 Agent 的转发服务器 | 入口 A、中转 B |
| 目标 | 最终连接的服务 | `192.0.2.10:443` 或 SS 分享链接 |
| 链路 | 由节点和目标组成的拓扑 | 入口 A → 中转 B → 目标 |
| 配置 | 一个入口与一个目标对应的连接信息 | 入口地址、SS／VLESS 导入链接 |

1. **接入节点**：按[节点 Agent](#节点-agent)完成安装，确认 IP 已识别。
2. **添加目标**：在“目标”中添加 IPv4／域名和端口，或导入 SS／SS2022／VLESS Reality 分享链接。
3. **创建链路**：进入“链路 → 新增链路”，点击“添加”，放入入口、需要的中转节点和目标。从起点右侧的 IP 圆点拖线到终点左侧的 IP 圆点。
4. **保存并同步**：点击“保存”，系统校验连线并自动排版。节点离线也可保存；后台待节点就绪后下发。主动节点和已启用唤醒的被动节点自动同步；其余被动节点运行 `sudo ictl --sync`。
5. **连接使用**：显示“已应用”后，在“配置”中复制入口地址或导入链接，也可以加入[订阅](#订阅)。

### 节点与 IP

节点列表的「标签」可管理标签名称和颜色；编辑节点时可多选标签，列表支持按标签筛选。链路编辑的添加列表同步显示标签，并沿用节点分组与组内排序。

每个节点有一个**主 IP**和多个可选**副 IP**。主 IP 是默认联系地址，实际连接来源在详情中单独显示；修改主 IP 保留节点密钥。

在“节点 → 编辑”填写别人能连接到的 IP；需要多个地址时点击“＋ 副 IP”，名称可留空。输入框提供 Agent 已识别的本机地址供选择，也支持手动填写云平台公网 IP。**接收地址不要求绑定在本机网卡上**，但外部流量必须确实能够到达节点。

画布左侧连接点选择接收 IP，右侧选择“自动出口”或某个指定 IP：

- **自动出口**：由系统路由决定源 IP，普通服务器和云平台 NAT 通常选它。
- **指定 IP**：按所选 IP 发出；若公网 IP 由服务商映射，在该地址的“高级设置”中填写对应的本机源 IP。网卡自动识别，特殊路由可手动选择网卡、网关。无法使用指定出口时会报错，不会改用其他出口。

要修改连线，选中线后更改发出／接收 IP。选中入口可设置“入口接收 IP”，生成的配置使用该地址。主副 IP 可以是任意 IPv4 组合；把副 IP 设为主 IP 不改变已有连线。面板不负责向网卡添加 IP，也不能改变服务商的公网映射。

已生效或正在下发的地址不能直接替换：先新增地址，在链路中替换并应用，再移除旧地址。尚未下发的地址设置可以直接修正，相关配置会自动继续同步；删除地址前仍需移除对应连线。暂未收到网卡信息时会等待采集完成，不需要反复保存。

### 多入口、多目标与配置

一张画布可以包含多个入口和目标，共享中间网络。**每个入口只为沿连线可达的目标生成配置**，不可达的组合不生成，最多 64 条。A 可达 C、D，B 只可达 D 时，就生成 A-C、A-D、B-D 三条配置；同一入口的不同目标可以走不同首跳。

每条配置有独立入口端口、固定 ID（如 `C0017`）和可修改名称，默认名称为“配置 0017”。入口端口留空时自动分配；手动指定时，在链路编辑中选中入口，再选择对应目标填写端口。增加副 IP 不会自动增加配置。

在“配置”点击“改名”即可修改名称。改名和中间路径切换不改变配置 ID、入口端口及订阅绑定；更换入口地址或端口后，需更新客户端连接信息。导入链接和订阅仅使用配置名称，Clash 遇到重名或保留名称时会附加 ID。

节点、目标和链路支持分组、排序与筛选。配置跟随链路的分组和排序，无需单独设置。

### 编辑与切换路径

编辑时可自由拖动节点，点击“整理”调整布局，保存时自动排版。入口位于第 0 层，中间节点按最长上游路径分层，目标集中在末列；共享节点只显示一次，未连通节点单独排列。画布支持缩放、平移、全屏、撤销和重做；只沿明确画出的连线选路，不允许同一路径重复经过同一服务器。

- **逐跳选择**：点击入口，再按高亮依次选择下一跳。选到最后一个转发节点后自动接上可达目标，无需再点击目标；也可点击“自动补全”。点击已选节点可退回该步，Esc 取消选路。
- **快速切换**：直接点击中间节点。系统尽量保留当前已生效的上游路径，只有无法接入所选节点时才逐级向前重选；各入口—目标独立处理。悬停可查看受影响的配置。
- **独立选路**：各入口—目标配置分别选路，无需统一首跳。原路径仍合法时优先保留，否则选择权重和最高的可达路径，同分时优先较短路径；不会因为节点离线而拒绝保存。

目标可在编辑窗口添加多个接入 `IP:端口`（也支持域名），共用原导入协议和认证信息。画布上连接到目标对应的地址圆点，或选中连线修改接收地址；不同连线互不影响。修改地址后只有引用它的配置重新同步；被引用地址需解除连线并等待同步完成才能删除。

目标只需连接能够访问它的节点。例如只有 C 能访问某个目标，就画 `C → 目标`，其他路径通过 C 到达它，不必为所有节点添加到目标的连线。

每个入口有自己的颜色。实线表示已确认路径，虚线表示等待同步的新路径；动画不代表实际流量。每条配置分别经过“准备下游 → 确认 → 切换入口 → 确认 → 清理旧规则”，共用节点的操作依次进行。下发期间仍可继续编辑；准备失败保留原路，入口切换失败尝试恢复原路。超过 30 秒未确认会等待处理，晚到的有效回执仍可完成切换。配置页和订阅使用已确认的连接信息。

### 权重与自动灾备

在“节点 → 编辑”设置整数权重，默认 **0**，可正可负，越高越优先；同一个节点的权重作用于所有链路。需要单独调整某条连线时，编辑链路、选中线、点击“＋ direct”，再设置它的权重。`direct` 只修正这条线的权重，不代表服务器，不新增端口、转发或探测跳数；移除它会接回原连线。

候选路径得分为**中间节点权重之和 + direct 权重之和**，入口和目标不计分。修改权重不切换健康路径，手动选路仍优先。

在链路详情打开“自动灾备”后：

- 只关注正在使用的主动中间节点：持续失联 **60 秒**，或 Agent 连续 **30 秒**确认已应用规则异常时，触发灾备。入口、目标和被动节点不作为故障触发源；不会根据延迟或丢包自动换路。
- 各入口—目标配置独立处理。从故障节点的上一跳寻找备用后缀，无路可走再向入口回退；选择可用候选中权重和最高的路径，同分随机选择。健康节点需稳定 **30 秒**才作为候选。
- 保留入口、目标、配置 ID 和入口端口。切换仍需下游和入口确认；明确下发失败时最多尝试 3 条候选，回执未知时等待确认。没有可用路径时保留现有配置并显示原因。
- 不自动切回恢复后的高权重节点。手动编辑或切换优先；默认关闭自动灾备，升级不会自行开启。

被动节点不主动报告健康，不能作为新备用节点。原路径上的被动节点须启用远程唤醒才能参与自动交接；被动入口也须启用远程唤醒，否则等待手动操作。

服务端不可用时，节点保留已有转发规则。新旧路径交接允许短暂断线，清理确认前仍需保留旧规则占用的端口。

## 主动与被动模式

| 行为 | 主动模式 | 被动模式 |
| --- | --- | --- |
| 配置同步 | WSS 长连接，即时推送 | 默认手动，可选认证 UDP 唤醒 |
| 面板修改后 | 自动获取并应用 | 启用唤醒则自动同步，超时后等待手动操作 |
| 开机后 | 恢复规则，再建立管理连接 | 只恢复已应用规则，不联网、不刷新域名 |
| 状态条 | 每格 20 秒，显示最近 20 分钟 | 每格 60 秒，显示最近 1 小时；白底，同步活动标绿 |
| 长时间无上报 | 30 秒后显示离线 | 不因时间流逝判离线 |

主动和被动节点均可作为入口或中间节点。被动同步按“上报 → 获取配置 → 应用 → 上报结果”执行；绿色活动标记不替代配置成功确认，具体结果看节点状态和事件。

### 切换模式

1. 在面板编辑节点，选择目标模式并保存。
2. 到节点运行 `sudo ictl --sync`，或在管理菜单选择“同步更新／确认切换”。
3. 等待本机确认成功，再检查面板状态。

两种方向都需要替换 Agent 程序，不能只修改本地模式文件。主动切被动时，收到通知的 Agent 会停止管理通信和采集，现有规则继续转发；离线节点需先收到通知。被动切主动依靠本机操作。交接失败按提示运行 `sudo ictl --recover`；首次安装尚无 `ictl` 命令时，可用 `sudo bash /usr/local/lib/ictl/manage.sh --recover`。

### 数据与诊断

主动节点详情提供 CPU、内存、磁盘、网卡速率、端口和转发流量。主要指标每 10 秒采集，端口每 30 秒、基础信息每 60 秒更新；“诊断”可按需查询系统、网络、规则、日志及目标连接。

转发流量按本节点规则、TCP／UDP 和上下行统计，包含协议头和重传，不等于应用下载量或全机网卡流量，多跳不要直接相加。切换后保留历史累计值；异常掉电等情况可能造成缺口，面板会标注可识别的缺口。被动节点不新增流量采集，历史值保留。

## 订阅

反向代理需将 `/sub/` 路径转发到服务端。

1. 在“配置”之后的“订阅”面板新增订阅，填写名称，勾选需要分享的配置；可使用“全选”。
2. 复制 **Clash 链接**或 **v2rayN 链接**，在客户端添加订阅。VLESS Reality 使用支持 Mihomo 的客户端。
3. 修改链路或配置名称后，在客户端更新订阅。条目使用配置名称，顺序跟随链路分组和排序。

SS／SS2022 和 VLESS Reality 可导出；仅 IP＋端口的配置不能作为代理订阅项。不支持的插件或传输参数会在绑定列表提示，对应格式会跳过该项。

持有订阅链接即可获取绑定配置的代理凭据，请只分享给需要的人。禁用、删除或重置链接后，旧链接立即失效，但已获取的凭据不会因此撤销。

## 被动节点远程唤醒

此功能默认关闭。被动节点不轮询、不保持管理长连接，收到有效的认证唤醒包后才同步配置。

1. 在节点运行 `sudo ictl --wake-settings`，选择“设置并启用”。
2. 填写未使用的 UDP 端口和 **Server 的实际出口 IP**。多个 IP 用英文逗号分隔，白名单不能为空；唤醒组件支持 amd64／arm64。
3. 在面板编辑对应被动节点，填写相同的唤醒端口并开启“被动节点远程唤醒”。云安全组需允许 Server 访问该 UDP 端口。
4. 之后配置变更会自动触发同步。Server 在第 0、10、20 秒尝试唤醒；30 秒内没有成功回执，显示“同步超时，等待手动同步”。

在网络允许的情况下，非白名单来源收到 ICMP“端口不可达”；白名单来源无论认证结果如何都不会收到唤醒回复。认证通过后的配置同步仍会产生正常的网络通信。

在节点菜单关闭功能会停止监听并清理专用规则；只关闭面板开关不会撤销节点上的本地授权。Server 出口 IP 变化后，需手动更新白名单。Agent 程序升级和模式切换仍需本机确认。

## 网络质量监测

在链路详情点击“网络质量”，选择入口与目标对应的配置，查看当前路径的全段和分段图，无需逐个选择节点。例如 `入口 A → B → C → 目标` 显示 `B → C → 目标`、`B → C`、`C → 目标` 三张图，不测量入口 A。

- **TCP（黄色）**：沿生效路径测量建连时间，不发送应用数据。
- **UDP（蓝色）／ICMP（绿色）**：测量主动节点之间的网络质量；目标支持 Ping 时，末段也可显示 ICMP。
- 被动节点不发起探测，但可参与转发。无法测量的片段显示“×／未知”。

支持 **15 分钟、1 小时、24 小时、7 天**视图。悬停曲线或使用左右方向键查看数据，悬停协议标签可突出对应曲线。统计包括平均延迟、P95、波动和探测超时率；探测超时率不等于业务丢包率。

默认每项每 **10 秒**采样，关闭网页仍会采集，历史保留 **7 天**。相同探测由统一任务共享，相关链路读取同一份结果，并各自保留切换历史。每个节点最多参与一次新探测／秒，任务较多时会排队。

节点之间需允许 **UDP 33445**（或节点设置的探测端口）及按需允许 ICMP Echo，程序不会自动开放防火墙。将节点的质量探测端口设为 `0` 可关闭其质量探测。采样不修改转发规则，也不参与自动选路。

## 单机脚本与共存

### 使用单机脚本

运行 `sudo bash /root/ipt.sh`，选择“添加转发”，填写本机入站端口、目标 IPv4／域名、目标端口、协议（`tcp`、`udp` 或 `both`）和备注。确认后可通过“本机地址:入站端口”访问目标，需同时放行安全组和防火墙。

菜单支持查看、修改、删除转发，导出、导入配置和恢复备份；输入 `q` 可取消当前输入。脚本配置开机恢复，并每 5 分钟刷新域名目标。备份恢复只处理单机脚本自身的转发。

### 与 Agent 共存

两者可单独运行，也可在同一台服务器使用，无需额外开关。双方检查本机服务、现有规则及对方已保存的端口。**同一协议的入站端口不能重复使用；Agent 同时占用 TCP 和 UDP。** 例如 Agent 使用 `10000` 后，单机脚本应选择其他入站端口。

发生冲突时，Agent 拒绝新配置、保留原规则并上报异常；单机脚本取消本次操作，返回菜单。根据报错处理相应节点的端口占用，或在链路编辑中调整入口端口后重新保存，不会自动换端口。

若已通过移除其他占用解决冲突，运行 `sudo ictl --sync` 重新检查。仅停止另一方服务不会释放它已保存的端口，需要删除或修改对应配置。

## 常见问题

**打不开面板，或访问端口后显示 404？**

请使用安装时输出的完整面板地址，其中包含随机路径。忘记地址可用上表中的查询命令；仍无法访问时，检查日志、端口放行和反向代理。

**配置一直“等待中”？**

查看链路详情中的阶段和节点错误。未启用唤醒、唤醒超时的被动节点，以及切换模式后的节点，需本机运行 `sudo ictl --sync`。主动节点检查服务和网络。新路径收到成功回执后才显示“已应用”。

**找不到副 IP，或提示指定出口不可用？**

可直接手填接收地址，不必等待识别。主动节点自动采集本机地址，被动节点在同步时采集。指定出口需有可用的本机源 IP 和路由；普通转发可改用“自动出口”。NAT 公网映射由服务商决定。

**保存成功，但配置没有出现或未生效？**

检查入口是否沿连线可达目标，不可达的组合不会生成配置。已生成的配置如果正在等待，查看路径上的节点是否上线、升级完成或需要手动同步；拓扑保存成功不代表规则已经生效。

**节点显示“端口冲突”或“端口检查失败”？**

按[共存说明](#与-agent-共存)处理占用。提示缺少 `ss` 时，安装 iproute2（部分发行版名为 iproute）。排除错误后运行 `sudo ictl --sync`，普通心跳不会清除冲突异常。

**节点认证失败或提示时间不一致？**

确认节点使用当前详情页中的接入地址和密钥，服务端与节点时差需在 60 秒内。修改主 IP 会保留密钥；手动重置密钥后，需运行 `sudo ictl --credentials` 更新本机接入信息。

**显示“已应用”但无法连接？**

这表示规则已确认，不代表目标连通性已通过测试。检查入口端口、每一跳的地址与回程路由、目标服务及防火墙。当前转发仅支持 IPv4，域名需能解析到可用的 IPv4 地址。

**升级后需要回退怎么办？**

先停止服务，恢复[升级说明](#服务端升级)中的升级前数据库及对应旧镜像，移除新数据库的 `-wal`／`-shm` 文件后再启动。回退会丢弃升级后的数据；源码部署或自定义数据库路径需自行备份和恢复。
