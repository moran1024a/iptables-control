# iptables-control（ictl）

轻量的 IPv4 端口转发管理工具，通过 Web 面板统一管理多台服务器的端口转发规则，也可以使用 `ipt.sh` 在单台服务器上独立管理。

支持多跳链路、SS／SS2022／VLESS Reality 目标、主动与被动同步，以及 Agent 与单机脚本共存。

**当前正式版：0.4.2**。支持池模板、可视化链路、手动优先级及节点失联灾备。主动节点使用 Go + nftables 和长连接，被动节点使用 Bash + iptables，可选择开启认证唤醒。转发节点无需安装代理核心，目标服务需自行准备。

## 安装

按使用场景选择：管理多台服务器，安装**服务端 + 节点 Agent**；只管理本机转发，安装**单机脚本**即可。以下命令固定使用 0.4.2 正式版；旧版用户升级前请先阅读[升级说明](#升级)。

### 服务端

准备一台已安装并启动 Docker 的 Linux 服务器，使用有 Docker 权限的账号执行：

```bash
curl -fsSL https://github.com/moran1024a/iptables-control/releases/download/v0.4.2/install-server.sh | bash
```

安装完成后，打开输出的**完整面板地址**。默认账号为 `admin`，密码为 `admin_pass`，首次登录必须修改。

默认端口为 `8730`，容器名为 `ictl-server`，数据卷为 `ictl-data`。如需指定端口或使用国内镜像：

```bash
curl -fsSL https://github.com/moran1024a/iptables-control/releases/download/v0.4.2/install-server.sh | bash -s -- --port 9000 --mirror
```

新主动 Agent 必须使用有可信证书的 HTTPS。请配置支持 WebSocket 的反向代理，转发至服务端的实际端口（默认 `8730`），并在面板“设置 → 对外地址”填写节点可访问的 HTTPS 地址，再接入节点。

### 节点 Agent

节点需要使用 systemd 的 Linux，并以 root 权限安装。

- **主动**：amd64／arm64，Linux 5.10+、nftables 1.0+、iproute2、conntrack-tools，使用 HTTPS／WSS。
- **被动**：Bash、iptables（含 save／restore、addrtype、conntrack）、iproute2、getent、conntrack-tools。
- 两者都需要 curl、openssl 1.1.1+ 和 flock。安装器可在 Debian／Ubuntu 安装缺少的依赖，其他系统请先自行安装。

1. 在面板“节点 → 新增节点”中填写名称、入站 IPv4／域名、允许的入站端口，首次使用可保留“主动”模式。
2. 打开节点详情，复制“一键接入”命令，在**对应节点服务器**执行。
3. 回到面板确认节点状态；以后可在节点运行 `sudo ictl` 打开管理菜单。

入站地址用于客户端或上一跳节点连接此节点。允许端口可填写 `10000-20000,30000` 这样的范围和列表，并需在云安全组及系统防火墙中允许相应 TCP／UDP 流量。

### 单机脚本

不需要服务端或 Agent。在使用 systemd 的 Linux 服务器执行：

```bash
curl -fsSL https://github.com/moran1024a/iptables-control/releases/download/v0.4.2/ipt.sh -o ipt.sh.download &&
sudo install -m 755 ipt.sh.download /root/ipt.sh.new &&
sudo mv -f /root/ipt.sh.new /root/ipt.sh &&
sudo bash /root/ipt.sh
```

首次运行会检查并安装缺少的 Python 3.8+、iptables 和 iproute2 软件包。后续运行 `sudo bash /root/ipt.sh` 即可进入菜单，具体操作见[单机脚本与共存](#单机脚本与共存)。

## 升级

**顺序：先升级服务端，再升级节点 Agent 和单机脚本。** 共存时，Agent 和单机脚本都需要升级到支持共存的版本，见[组件版本](#组件版本)。

### 服务端升级

0.4.0 的 Docker 安装器会因健康检查误判而回滚，请直接使用 0.4.2 安装命令重试。已经回滚到 0.3.x 的服务端无需手动恢复数据库；0.3.x 节点的迁移方式仍见下文。

重新执行[服务端安装命令](#服务端)即可。安装器沿用现有端口和数据挂载，保留升级前数据库备份；新容器启动或就绪检查失败时尝试恢复旧容器和数据库。相同版本需要重建时，将命令末尾的 `| bash` 改为 `| bash -s -- --force`。

**从 0.3.x 升级到 0.4.x：只保留节点、目标及其分组，旧链路、转发配置和运行历史全部清空，需要重新创建链路。** 节点密钥、目标连接参数以及登录和接入地址等服务端设置保留。旧 Agent 在下一次成功同步时清理原转发规则；被动节点需要本机手动同步。清理确认前，原端口仍标记为占用，不能分配给新链路。升级前数据库备份为 `ictl.db.pre-0.4.0.bak`。

> 从 0.2.x 或更早版本升级：数据库中的全部隧道节点、受管隧道及其关联配置会被删除。对应远端的旧隧道 Agent、sing-box 和配置文件需自行卸载。外部导入的 SS／VLESS 会转为“目标”；进入 0.4.0 时仍按上面的规则清空旧链路和转发配置。详情见 [更新记录](CHANGELOG.md)。

### 节点 Agent 升级

**0.4.2 修复主动 Agent 在 nftables 1.0.6 上安装失败，以及被动 Agent 与单机脚本共存时 UDP 唤醒端口误报冲突的问题。** 请先升级服务端，再更新 Agent。此前安装失败并留下 `switch-work` 的节点，请保留该目录，从升级后的节点详情重新复制“一键接入”命令执行；安装器会核对并恢复本次空表残留。已经正常安装的被动节点运行 `sudo ictl --update` 后，重新设置唤醒端口即可。

**服务端升级不会把旧 Bash Agent 自动替换为 Go。** 旧节点继续使用 Agent 0.2.1；要迁移到新版，请在节点详情中重新复制“一键接入”命令执行。安装器保留节点身份和配置，并根据面板所选模式安装对应 Agent。

旧被动节点升级前，需要先安装 `conntrack-tools`。Debian／Ubuntu 可运行 `sudo apt-get install conntrack`；重新运行新版一键接入安装器也会检查依赖。

已完成迁移的节点可执行：

```bash
sudo ictl --update  # 只更新当前类型
sudo ictl --sync    # 同步配置，或确认面板要求的类型切换
```

新版主动 Agent 在 `AUTO_UPDATE=1` 时接受同类型更新通知；被动 Agent 程序仅在本机手动操作时更新；远程唤醒只同步转发配置。可在 `/etc/ictl/agent.conf` 将 `AUTO_UPDATE` 设为 `0` 关闭主动自动更新，随后重启 `ictl-agent`。手动 `--update` 不受此开关限制。

迁移会替换可识别的 `/root/ictl.sh`、`/ictl.sh` 旧入口，使其指向新版 `ictl`。后端交接期间允许短暂断线；已有防火墙若默认拒绝 FORWARD，需要先明确放行自己的转发范围。

### 单机脚本升级

重新执行[单机脚本安装命令](#单机脚本)。**如果原脚本不在 `/root/ipt.sh`，请将命令中的安装路径改为原路径**，保证开机任务和定时任务运行新版。更新后进入菜单检查转发列表。

## 切换主动与被动

1. 在面板编辑节点，选择目标模式并保存。
2. 到该节点运行 `sudo ictl --sync`，或在 `sudo ictl` 菜单选择“同步更新／确认切换”。
3. 等待显示确认成功，再检查面板状态。

主动切被动时，收到通知的 Agent 会停止管理通信和采集，现有规则继续转发；若节点已经失联，停用通知需等重新连接后才能送达。被动切主动完全依靠本机操作。**两种方向都要替换 Agent 程序，不能只修改本地模式文件。**

切换工具先准备组件与配置，再备份、交接规则，最后向服务端确认。下载失败不动旧规则；交接失败尝试恢复。确认响应丢失时，重新运行 `sudo ictl --sync`；提示交接中断时，按提示运行 `sudo ictl --recover` 后重试。首次安装尚未生成 `ictl` 时，可用 `sudo bash /usr/local/lib/ictl/manage.sh --recover`。

## 卸载与删除

### 卸载服务端

删除容器和镜像，保留数据卷，之后可重新安装恢复使用：

```bash
curl -fsSL https://github.com/moran1024a/iptables-control/releases/download/v0.4.2/install-server.sh | bash -s -- --uninstall
```

追加 `--purge` 会永久删除默认数据卷中的全部数据。卸载服务端不会清理远端节点规则；若要完整停用，请先处理节点。

### 卸载节点 Agent

1. 在面板切换使用该节点的链路，等待旧规则清理，再解除池和固定节点引用，删除节点。
2. 等待节点完成清理同步；未启用远程唤醒或唤醒失败的被动节点，需在本机运行 `sudo ictl --sync`。
3. 清理确认后，在节点卸载 Agent：

```bash
sudo ictl --uninstall
```

命令会询问确认，并删除该 Agent 的规则、配置和服务；非交互执行可加 `-y`。旧隧道节点需使用对应旧 Release 的 `install-tunnel.sh --uninstall` 自行卸载。

### 停用单机脚本

当前没有一键卸载命令。先运行 `sudo bash /root/ipt.sh`，通过“删除转发”清空由它管理的转发，再停用开机恢复和定时刷新：

```bash
sudo systemctl disable --now ipt-forward-selfcheck.timer ipt-forward-selfcheck.service
```

完成后可删除脚本文件。配置目录 `/root/iptables-forward-conf/` 和备份目录 `/root/iptables-backup/` 可按需保留；仅删除脚本或停止服务不会清除现有转发规则。

### 删除面板对象

被引用的池不能删除。正在使用、锁定、切换中或等待旧规则清理的池成员不能移除；页面会指出相关链路。删除链路后，等待节点确认清理才释放端口。目标和节点需先解除引用；配置页仅汇总连接信息。

## 使用指南

### 创建第一条转发

| 对象 | 用途 | 示例 |
| --- | --- | --- |
| 节点 | 安装了 Agent 的转发服务器 | 入口服务器 A、中转服务器 B |
| 目标 | 最终连接的服务 | `192.0.2.10:443` 或导入的 SS 节点 |
| 池 | 可复用的主动节点候选模板 | 香港 A、香港 B |
| 链路 | 固定入口、池或固定中间节点，以及一个目标 | 入口 → 香港池 → 目标 |
| 配置 | 自动汇总每条链路的连接信息 | 入口地址、SS／VLESS 导入链接 |

接入节点后，按以下步骤操作：

1. **添加目标**：进入“目标”，点击“添加地址目标”填写实际 IPv4／域名和端口；已有 SS／SS2022／VLESS Reality 分享链接时，选择“导入分享链接”。
2. **创建池（可选）**：进入“池”，添加已确认的主动节点，可搜索并批量添加成员，拖动或使用上下按钮调整初始优先级。一个节点可以属于多个池。
3. **创建链路**：选择入口、入口端口、中间池或固定节点及目标，可拖动调整中间路径顺序，点击“保存并应用”。入口端口留空自动分配，内部端口由服务端管理；也可以保存草稿。
4. **等待生效**：主动节点和已启用远程唤醒的被动节点自动同步；其余被动节点或唤醒超时的节点，运行 `sudo ictl --sync`。配置显示“已应用”后，说明相关节点已确认规则。
5. **连接使用**：在“配置”中复制入口地址或 SS／VLESS 导入链接。编辑路径时，从配置名称进入对应链路。

选择“无入口（直达目标）”且不添加中间阶段时，直接使用目标地址。池模板和链路草稿不占用转发端口。

节点和目标保留原有分组、排序与筛选。更换入口节点或入口端口后，需要更新客户端的连接信息；池成员切换保持入口不变。

池、链路和配置列表支持搜索与状态筛选。链路画布可全屏、缩放和平移，点击“当前路径”聚焦已确认节点；点击两个主动节点之间的连线，可查看 UDP／ICMP 曲线。离开有修改的弹窗前会提醒保存，保存失败会保留输入。

### 池与灾备切换

链路详情会展开每个池的全部成员。绿色线条及动画表示已确认的生效路径，黄色虚线表示待确认的新路径；动画不代表真实流量。点击候选节点并确认，可将它设为本链路的默认节点并切换，优先级及显示顺序不变。画布支持拖动、滚轮或双指缩放，首次打开自动适应全部节点；刷新保留视角。

池右上角的“设置”可调整完整优先级、锁定和禁用，也可以添加“直连下一阶段”候选，仅跳过对应池。新建实例以最高优先级的节点作为默认节点；之后默认节点与灾备优先级独立维护。锁定后不自动灾备。离线、禁用或受锁定限制的成员不能快速切换。切换请求被接受后会保留所选默认节点；实际生效仍以节点回执为准。灾备按其余成员的优先级选择，不修改默认节点，也不因默认节点恢复而自动切回。

模板的排序只影响以后添加的实例。新增模板成员会追加到已有实例末尾；移除成员会同步到实例，但正在使用的成员须先切换并等待清理完成。修改某条链路的设置不会影响其他链路。

当前主动成员持续失联 **60 秒**后，服务端按优先级尝试可用成员；成员恢复后不自动切回。首版只处理节点失联，不根据延迟或丢包自动择优，也不检测所有业务链路故障。服务端不可用时保留节点现有规则。

切换先准备下游，再修改入口，收到确认后显示生效；可能短暂断线。新旧路径短时共存，内部节点需有空闲转发端口。等待超过 30 秒会显示待人工处理，晚到回执仍可完成切换。旧规则未确认清理时继续保留端口，不能移除相关成员。遇到端口冲突，修改配置或处理占用后再重试，不自动换端口；灾备可继续尝试其他候选节点。

被动节点只能作为固定节点；参与池切换前，手动升级到 0.4.0 并安装 conntrack-tools。未开启远程唤醒时，需要在每个待同步阶段运行 `sudo ictl --sync`。

从 RC1–RC3 升级到 0.4.0 时，会备份数据库，将每条旧配置转换为一个固定路径链路组，保留原入口、端口、目标和规则；未使用的旧链路保留为草稿。0.3.x 升级则按前述规则清空旧链路和配置。RC4 及之后的版本升级保留已有池和链路。升级不会自动增加池。

### 主动与被动模式

| 行为 | 主动模式 | 被动模式 |
| --- | --- | --- |
| 配置同步 | WSS 长连接，配置变更即时推送 | 默认手动，可选认证 UDP 唤醒 |
| 面板修改后 | 自动获取并应用 | 启用唤醒则自动同步，30 秒超时后等待手动同步 |
| 开机后 | 离线恢复规则，然后建立管理连接 | 只恢复已应用规则，不联网、不刷新域名 |
| 状态条 | 每格 20 秒，显示最近 20 分钟 | 每格 60 秒，显示最近 1 小时；白底，手动同步活动或远程同步成功标绿 |
| 长时间无上报 | 新主动 30 秒；旧版轮询 120 秒 | 不因时间流逝判离线 |

模式切换见[切换主动与被动](#切换主动与被动)。同步先上报，再获取并应用配置，最后上报结果。失败原因见节点详情和事件；被动状态条的绿色只表示发生了同步，是否成功以状态和事件为准。

### 主动节点的数据与诊断

节点详情可查看 CPU、内存、磁盘、网卡速率、端口快照和转发流量；每 10 秒采集主要指标，端口每 30 秒更新，基础信息每 60 秒更新。也可以请求系统、端口、网络、规则、最近日志，以及对当前转发的连接查询和目标诊断。断线期间本地累计流量保留，重连后补报；普通配置切换不会清空累计值。

流量按**本节点、每条转发、TCP／UDP、上下行**分别统计 IPv4 字节，包含协议头和重传。它不是应用下载量，也不是全机网卡流量；多跳不要直接相加。数字以整数保存，重复上报不会重复累加。意外掉电、外部清零或 flowtable 卸载可能造成缺口，可识别的缺口会在面板标明，不能当作完整账单。被动模式不新增采集，历史值保留。

池切换会归档旧规则的流量记录，历史累计值保留。

## 被动节点远程唤醒

此功能默认关闭。被动节点不轮询、不保持管理长连接；启用后只有收到有效的认证唤醒包才主动同步配置。

1. 先手动升级被动 Agent，再在节点运行 `sudo ictl --wake-settings`（或菜单 5）。
2. 选择“设置并启用”，填写一个未使用的 UDP 端口和 **Server 的实际出口 IP**。多个 IP 用英文逗号分隔，可填 IPv4／IPv6；白名单不能为空。监听组件支持 amd64／arm64，首次启用会下载同版本组件。
3. 在面板编辑对应被动节点，填写相同的唤醒端口并开启“被动节点远程唤醒”。节点需要能接收入站 UDP，云安全组也需允许 Server 访问。
4. 之后影响该节点的配置变更会自动触发同步。Server 在第 0、10、20 秒尝试唤醒，30 秒内没有收到对应配置的成功回执，就显示“同步超时，等待手动同步”。晚到的有效成功回执仍会恢复状态。

非白名单来源收到 ICMP“端口不可达”；白名单来源无论认证结果如何都收不到唤醒回复。认证通过后，节点通过现有同步地址上报、获取配置、应用并确认；这个后续连接仍会产生可观察的通信。白色状态条保留，远程同步成功标绿。

在节点菜单关闭功能会停止监听、清理专用规则；只关闭面板开关会停止 Server 的唤醒尝试，不会远程更改节点的本地授权。Server 出口 IP 变化后，需要在节点手动更新白名单。Agent 程序升级和主被动模式切换仍需本机确认。

## 网络质量监测

服务端升级后，在链路详情点击 **网络质量与趋势**。主动 Agent 需 RC2 或更新版本。

1. 在两个主动节点的防火墙／云安全组中，允许参与探测的节点访问 **UDP 33445**，并按需允许 **ICMP Echo（Ping）**。ICMP 不占用 TCP／UDP 端口，Agent 内置实现，不需要安装 ping 命令。程序不会自动修改防火墙。
2. 默认使用节点的入站地址。端口冲突时，在“编辑节点 → 质量探测 UDP 端口”修改；填写 `0` 可停止该节点的全部质量探测。已有转发规则保持原样。
3. 在同一张延迟图中对比 **蓝色 UDP** 与 **绿色 ICMP** 曲线；下方摘要表分别显示 RTT、最近 5 分钟平均值、P95、波动和探测丢包率。支持 **15 分钟、1 小时、24 小时**切换；悬停数据点查看详情。

实际路径及相邻池的候选主动节点之间，UDP 和 ICMP 各默认每 **10 秒**探测一次，错开调度，关闭网页后仍持续采集。同一节点对在多个链路中共享结果；每个节点最多参与一次新探测／秒，候选较多时排队，实际间隔会延长。也可在图表中选择链路内非相邻节点，查看期间按需探测，离开页面后约一分钟停止。全部历史保留 24 小时。

超时、离线、探测异常和未采样分别展示，缺失数据不当作 `0 ms`。丢包率同时显示失败次数与样本数，仅代表探测包，不等于业务流量丢包；短窗口样本少，宜结合趋势判断。UDP 使用独立认证小包，ICMP 使用系统 Echo 应答，分别统计；不做带宽测速，不会触发自动切换或修改转发规则。切为被动后停止参与探测，历史记录继续保留至到期。

> 图表测量节点间直达网络，不代表经过其他节点的整段业务链路。UDP 端口未放行、ICMP 被禁用或限速时可能显示相应协议超时；一种探测异常不阻止另一种，转发仍按原配置工作。旧版及 RC1 Agent 不参与质量探测，升级前会显示提示。

## 单机脚本与共存

### 使用单机脚本

运行 `sudo bash /root/ipt.sh`，选择“添加转发”，依次填写：

| 项目 | 填写说明 |
| --- | --- |
| 入站端口 | 本机接收连接的端口，例如 `10000` |
| 目标 IPv4／域名 | 最终服务的实际地址 |
| 目标端口 | 最终服务监听的端口，例如 `443` |
| 协议 | `tcp`、`udp` 或 `both`（两者） |
| 备注 | 用于辨认规则，支持字母、数字、`.`、`_`、`:`、`-` |

确认后即可通过“本机地址:入站端口”访问目标，请同时放行相应的云安全组和系统防火墙端口。菜单还支持查看、修改、删除转发，以及导出、导入配置和恢复备份。输入 `q` 可取消当前输入。

脚本会配置开机恢复；使用域名目标时，每 5 分钟刷新一次。备份恢复仅处理单机脚本自身的转发。

### 与 Agent 共存

两者可以单独运行，也可以在同一台服务器使用，无需额外开关。双方会检查本机服务、现有转发规则和对方已保存的端口。

**同一协议的入站端口不能重复使用；Agent 同时占用 TCP 和 UDP。** 例如 Agent 使用 `10000` 后，单机脚本不能再用 `10000` 作为 TCP 或 UDP 入站端口，应另选端口。

发生冲突时：

- **Agent**：拒绝本次新配置，保留原规则，并在同步上报后让面板显示“异常”。到“配置 → 编辑”修改冲突节点对应的端口，再等待主动同步或执行手动同步。
- **单机脚本**：提示冲突并取消本次操作，返回菜单。修改端口后重新操作即可。

新版主动 Agent 会采集端口供查看，但服务端仍照常下发配置，由本机最终检查，不会自动换端口。同一份冲突配置不会被 Agent 自动反复应用；如果已通过移除其他占用解决冲突，请运行 `sudo ictl --sync` 重新检查。仅停止另一方服务不会释放它已保存的端口，需删除或修改对应配置。

## 常见问题

**打不开面板，或访问端口后显示 404？**

请使用安装时输出的完整面板地址，其中包含随机生成的路径；忘记地址可用上表中的查询命令。仍无法访问时，检查容器日志、端口放行和反向代理配置。

**配置一直“等待中”？**

进入对应链路详情，查看当前阶段和节点错误。未启用唤醒、唤醒超时的被动节点和切换模式后的节点需要本机手动同步；主动节点则检查服务、网络和节点详情中的错误。新路径确认后才会显示“已应用”，旧规则清理状态单独展示。

**节点显示“端口冲突”或“端口检查失败”？**

查看节点详情中的具体原因。冲突按[共存说明](#与-agent-共存)修改端口；提示缺少 `ss` 时，安装系统的 iproute2 软件包（部分发行版名为 iproute）。排除错误后运行 `sudo ictl --sync`，重启或普通心跳不会清除冲突异常。

**节点认证失败或提示时间不一致？**

确认节点使用当前详情页中的同步地址和密钥，并检查服务端与节点的系统时间，时差需在 60 秒内。修改节点入站地址会重新生成密钥，需要更新本机接入信息。

**显示“已应用”但无法连接？**

“已应用”表示转发规则已确认，不代表已测试目标连通性。请检查入口端口、各跳网络和目标服务是否可达，以及云安全组和防火墙是否放行。当前仅支持 IPv4；域名需要能解析到可用的 IPv4 地址。

**升级后需要回退怎么办？**

Docker 安装器将升级前备份保存在数据卷内的 `/data/ictl.db.pre-deploy-*.bak`，池模式的数据迁移另保留 `ictl.db.pre-0.4.0-rc.4.bak`；此前 RC 的迁移备份也会保留。人工回退需停止服务，恢复升级前数据库及对应旧镜像，移除新数据库的 `-wal`／`-shm` 文件后再启动；回退会丢弃升级后的数据。源码部署或自定义数据库路径需自行备份和恢复。
